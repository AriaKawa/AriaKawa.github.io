Asset pack requirements

Every new style gets 14 newly generated, separate PNG images. No shared sheets or recolored copies. Characters and effects now use articulated animation, with one focused arcade edition.

Download the specification (JSON)

Style briefs

  • arcade2005 — Rounded DS-era arcade art, silver machinery, bright green inset floor panels, chunky brown bricks. Animation is the priority.

Production contract

  1. One new image-generation call per logical asset, no composite sprite sheets, no recolors of another style.
  2. Save exact prompts under asset-prompts/<style> and original output PNGs unchanged under dist/assets/<style>.
  3. Peanut: anthropomorphic peanut, propeller cap, white gloves and shoes.
  4. HutchMF: human, extremely heavyset with large belly, backwards black cap, beard, black polo, jeans, tattoo arms.
  5. Ninja: slender human, spiky blue hair, yellow headband, blue hoodie.
  6. Use consistent perspective, lighting, palette, silhouette and outline weights within each pack.
  7. All menu states receive their own illustration: paused, won, lost, roundWon. Character select uses the three individual character images.
  8. UI buttons, borders, indicators and accessibility labels are code-native controls themed with each pack, not images of text.
  9. Assets load atomically; never mix styles or silently substitute old assets. Disable Play during load and show a retryable error.
  10. Original images are preserved. Runtime alpha-bounds cropping only removes transparent padding for consistent display.
  11. Validate unique hashes and complete inventory, inspect each style in character selection, gameplay and menus at desktop and mobile sizes.
  12. Characters must use independent animated limbs and four directional views. A static sprite with whole-image rotation or bobbing is insufficient.
  13. Required animation states: idle breathing and blinking; alternating arm/leg walk; charge anticipation; crouch/reach bomb placement; hit recoil; death squash; victory jump.
  14. Environment animation: accelerating bomb pulse, placement bounce, burning fuse sparks, connected flame ignition and decay, brick debris, pickup rotation, warned bomb-rain descent.
  15. Pause must freeze gameplay animation and timers. Reduced motion must suppress cosmetic shake, bob and particles while keeping gameplay states readable.

Required path: dist/assets/<style>/<asset>.png. Use square canvases for game objects, full-body portraits for the cast and a wide canvas for the wordmark. Preserve original alpha. Runtime trims transparent padding and scales to the shared game grid. Generated source resolution must be at least 128 pixels on each side.

Acceptance checks

Run node validate-packs.mjs for complete inventory, PNG headers, minimum dimensions, and unique file hashes. Run npm test for shared game mechanics. Inspect all images for consistent style, transparent edges, legible silhouettes and correct character identities. Play each style on desktop and mobile; verify all four menu states and atomic style loading.

Bomb rain

Begins with 25 seconds left. Two marked drops every 2.5 seconds; increases to three every 1.1 seconds during the final 10 seconds. Landing markers last 1.2 seconds, followed by a 1.35-second fuse. Drops use empty floor cells, regular blast rules and chain reactions. Bots see the danger too. Pending drops reset between rounds.
